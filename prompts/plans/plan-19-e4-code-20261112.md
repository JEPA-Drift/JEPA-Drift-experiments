## 1. Décisions techniques

### D1 — Calibration scalaire commune (Q1 a)
- EW (`w=1/√N`), O-dir (`w=u_N`) et O-score1 (`w=v̂_{k*}`, base E4) partagent un détecteur unique. Le flux
  `x = 2·exact_sign_stream(X @ w, pipelines._coins(rec))` alimente `eprocess.log_edetector(x, "cusum")`, avec huit mises
  `2·side·η0` et la même règle de franchissement.
- Calibration : 2000 chemins `B ~ Bernoulli(1/2)` du domaine `scalar_cal` donnent `2B−1`, envoyé dans le même
  `log_edetector`. Le seuil `pdb.rank_threshold(maxima_log, .05, "GE")` est calculé une seule fois puis gelé dans la
  partition `scalar_cal` (D6). Toutes les cellules scalaires le relisent ; il ne sert jamais au holdout ni aux
  alternatives. Le FPR holdout est mesuré par (méthode, fond, N) ; les dictionnaires sont calibrés par cellule.

### D2 — Spectre : convention E4 locale, `eigh_desc` inchangé (Q2 a)
- `X_N = np.ascontiguousarray(X_fit[:, :N])` est formé une fois par cellule, puis transmis à `pdb.fit_basis` et aux
  `fit_pipeline` (D3). Aucun appelant partagé n'est modifié.
- `canonical_eigh(eigval, eigvec)` procède en quatre étapes :
  1. tolérance `tol = 64·np.finfo(np.float64).eps·max(1, eigval[0])`, fixée avant tout tirage ;
  2. écarts consécutifs : un écart `< 0` lève `ArithmeticError` ; un écart `<= tol` lève
     `EigenTieUnresolved("EIGENVALUE_TIE_UNRESOLVED", blocs, écarts)`, sans base canonique ni orientation arbitraire ;
  3. contrôle `np.argsort(-eigval, kind="stable") == arange(N)`, sinon `ArithmeticError` ;
  4. orientation exacte : `i* = argmax|v_k|` (premier indice), `s_k = sign(v_k[i*])`, `V_e4 = V·s`.
- La dérive n'oriente jamais la base. Le bloc N−1 de Σ_N est une nuisance déclarée : la règle n'identifie aucun axe.
- Un refus porte sur la base (fond, N). SPEC-prefix8, SPEC-full, P3-CS(b) et O-score1 reçoivent
  `EIGENVALUE_TIE_UNRESOLVED` et des métriques NA ; EW, O-dir et les lignes de statut restent publiés. Tout contraste
  dont la grille contient une cellule refusée passe `NOT_IDENTIFIED` (Δ, Δ_1, Δ_2 du fond). Ni sous-ensemble de N, ni
  nouvelle graine, ni nouvelle tolérance.
- Identité : `basis_hash_e4 = pdb.array_sha256(eigval, V_e4)`, calculé sur la base utilisée. Le `basis_hash` de
  `fit_basis` est conservé comme `basis_hash_legacy`, pour la seule provenance.
- `canonical_state(state, s)` opère sur une copie profonde. Il retourne exactement les colonnes de `rep.state["W"]`
  (PCAOrthogonal) ou de `rep.state["U"]` (DegreeZero, `s[1:]`) ; le signe de `b` est sans effet.
- Cohérence au bit près : `W_e4 == V_e4/√eigval`, `U_e4 == V_e4[:,1:]`, `|b| == |V_e4[:,0]|`, et un même
  `x_fit_sha256` pour tous les états.

### D3 — Adaptateur local du registre ; dérogation limitée à `run_pipeline`
- Le registre est inchangé, car une clé de plus dans `DEFAULTS` changerait tous les `run_id`. Les spécifications restent
  en `reading="anytime-valid"` :
  - SPEC-full : `make_spec("P3-C", mode="full", channels="all", H=2000, gamma=horizon_gamma(2000, .05))` ;
  - SPEC-prefix8 : idem avec `channels=list(range(8))` ;
  - P3-CS(b) : `make_spec("P3-CS", mode="full", H=2000, gamma=…)`.
- États : `fit_pipeline(spec, X_N, splits)` sur les lignes `fit` sans dérive, puis `canonical_state`, avec
  `splits = {"pretrain": (0,0), "calib": (0,T_fit), "pre_monitor": (0,T_fit), "dates": np.arange(T_fit).astype(
  "datetime64[D]")}`. `fit_cell` ajuste P3-C full et P3-CS(b) full. SPEC-prefix8 réutilise l'état P3-C full, le fit ne
  dépendant pas de `channels` ; un témoin vérifie l'égalité avec un fit dédié.
- `kernel_log_path(spec, x) -> (n, H)` appelle les noyaux de `PIPELINES[p][2]` :
  `log_dictionary_edetector(x, "cusum")` pour P3-C, `(x, "cusum", eta0=(pipelines.STAKE_CAP/2.0,))` pour P3-CS(b).
- `method_log_path(method, cell, X, rec) -> (H,)` renvoie soit le flux scalaire de D1, soit
  `PIPELINES[p][1](spec, state, X, rec)` passé à `kernel_log_path`, avec
  `rec = {"tau_star": 0, "seed": clé coins, "family": …}`.
- Dérogation déclarée sous `C-e4-registry-adapter` : `run_pipeline` n'est pas appelé, car ses lignes porteraient
  `anytime-valid` sans chemin log. La réutilisation se limite à `fit_pipeline`, aux constructeurs de flux et aux noyaux
  `eprocess`, sans runner générique. Témoin binaire sur les trois spécifications :
  `first_alarm(kernel_log_path(spec, x), spec["gamma"]) == PIPELINES[p][2](spec, state, x)`.

### D4 — Rang en espace log et contrat unique des jours d'alarme (Q5 a)
- Un chemin log par trajectoire sert aux deux lectures. Sur les maxima `max_{t<=H} log M_t` (float64),
  `h, r, alarms = pdb.rank_threshold(maxima, α, "GE")` donne `h = nextafter(b, +inf)` en espace log. On n'utilise ni
  `np.exp(h)`, ni gamma, ni `first_alarm` au seuil de rang.
- Contrat `first_hit ∈ {1,…,H} ∪ {−1}` ; le temps censuré vaut `first_hit` si > 0, sinon H.
  - Rang (`predictive_rank`) : `int(pdb.first_index((log_m >= h)[None, :])[0])`, helper scellé intact.
  - Secondaire (`anytime_valid_horizon`) : `off = eprocess.first_alarm(log_m, γ_H)` donne un offset 0..H−1 ou −1 ;
    `first_hit = off + 1` si `off >= 0`, sinon −1.
- `h` est stocké en `float.hex`. `InsufficientCalibration` et `CalibrationFailed` donnent `CALIBRATION_FAILED`, comme
  dans `pdb.calibrate`.

### D5 — Graines, appariement, identité scientifique
- `key19(seed, *parts) = [19, seed, *(pdb.label_code(p) if str else int(p))]`, car `pdb.seed_key` fixe STREAM=28.
  Domaines :
  - `innov` (rôle, i) : (T, 1+N_max), partagé par les deux fonds ;
  - `chi2_t7` (rôle, i) : `s_t = √(5/χ²_7)` ;
  - `coins` (rôle, i) ;
  - `direction` (i) : g ∈ R^N_max, partagé entre N et fonds ;
  - `boot` (alternative, holdout) : indices (B_boot, n) communs aux N et aux méthodes ;
  - `scalar_cal` (i) ;
  - `pilot` : `key19(42, "pilot", domaine, rôle, i)` pour tous les tirages du pilote.
- Rôles : `fit` (i=0), `calibration`, `holdout`, `alternative` et `scalar_calibration`. Le holdout O-dir/O-score1 suit
  la direction i (appariement déclaré). Avant tout tirage, CRC32 doit être injectif et `pdb.check_entropies` passe sur
  l'union science + pilote, suffixe 7 de `_coins` inclus. Aucun état PRNG global.
- Chemins tirés à N_max puis tronqués. Alternative : `x + c·u_N`, avec `u_N = P g_{1:N}/‖P g_{1:N}‖`,
  `c = √(2(1−ρ)I*)` et `I* = 40·ln(H/α)/H`.
- Environnement : `pdb.check_env()` ne fait que valider ; une liste de problèmes non vide entraîne un refus.
  L'instantané haché est distinct : Python, numpy, scipy, pandas, statsmodels, BLAS de numpy, `*_NUM_THREADS`,
  MKL_CBWR, PYTHONHASHSEED.
- FAIR : `pipelines.save_fair_csv`, SHA-256 complet de chaque fichier, relecture en `float_precision="round_trip"`.
  Workers, temps et RSS restent hors des CSV scientifiques et de l'identité. Sur fixtures, jobs=1, jobs=3 et l'ordre
  permuté produisent les mêmes octets.

### D6 — Sorties : identité de session, partitions, reprise atomique
- Racines distinctes : `results/e4_alignment/precheck_20261112/`, `results/e4_alignment/pilot_20261112/` et `tmp_path`
  pour les fixtures. Une campagne future aura la sienne, hors de ce lot. Le mode fait partie de l'identité.
- `session.json` fixe l'identité immuable : SHA-256 `pdb.canon` de {mode, configuration, SHA-256 du script et des
  modules réutilisés, instantané d'environnement, domaines, `seed_plan.sha256`}. Aucun objet réalisé n'y figure.
- Partitions : `precheck`, `scalar_cal` ou `<fond>:<N>` (dossier `<fond>_N<N>`), réplicats `[0, n)`.
  `partition.json` contient {id, session_id, identité, statut, SHA-256 complet de chaque fichier, hashes des objets
  réalisés quand le stade les produit : `basis_hash_e4`, `calibration_hash` hors pilote, aucun dans le pilote}.
- Écriture dans `partitions/<dossier>.tmp-<pid>/`, puis `os.replace` atomique ; statuts finals `COMPLETE` et
  `BLOCKED_RESOURCE`. Cas contrôlés avant toute écriture :
  1. sortie nouvelle : création atomique de `session.json`, puis calcul ;
  2. `session.json` identique : continuation, sans échec dû à son existence ;
  3. partition `COMPLETE` aux SHA-256 concordants : `SKIPPED_COMPLETE`, sans recalcul ni octet modifié ;
  4. partition `BLOCKED_RESOURCE` : jamais un succès ; relance automatique refusée, décision requise ;
  5. `.tmp-*` sans dossier final : partition incomplète, jamais un succès, recalculée dans un nouveau dossier temporaire ;
     les restes sont signalés, ni lus ni supprimés ;
  6. divergence (session, partition ou SHA-256 final) : `pdb.PartitionMismatch`, sans mutation.
- Codes de sortie : 0 `COMPLETE`/`SKIPPED_COMPLETE`, 3 full refusé, 4 `BLOCKED_RESOURCE`, 5 refus d'identité ou de
  reprise. Reprendre, c'est relancer exactement la même commande.

### D7 — Pilote coût : mesures, limites, sorties contrôlées
- 40 réplicats par rôle dans le domaine `pilot`, mêmes H, N, T_fit et méthodes. `--jobs 1` est imposé et toute autre
  valeur refusée ; les témoins jobs=3 restent sur fixtures.

  En sériel, `RUSAGE_CHILDREN` n'est pas utilisé ; une prévision parallèle reste une hypothèse.
- Limites :

    refuser si `VmRSS` + estimation > 8 GiB ;

    borne le retard.
- `BLOCKED_RESOURCE` : la partition garde les stades achevés et liste le reste `NOT_MEASURED`. Les N plus grands du même
  fond ne sont pas lancés et restent `NOT_MEASURED`. La prévision passe `INCOMPLETE`, d'où STOP. La grille ne change pas ;
  seuls les replis approuvés, dans l'ordre, peuvent être proposés.
